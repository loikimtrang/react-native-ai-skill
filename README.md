# react-native-ai-skill — generic Expo/Ignite React Native tech stack

A **tech stack** for `tech-stack-vault`: this repo's tree is a `.claude/` payload that gets
downloaded into a project's local `.claude/` by **`/init-project`**. It carries the conventions for
an **Expo + React Native (Ignite-flavored MVVM)** app, so Claude builds features the way this
codebase already works — and builds screens that match the Figma design.

## Reference stack

TypeScript-first Expo/React Native, functional components + MobX (`observer`) for reactivity, MVVM
via `BaseViewModel` (MobX class) + `Screen` function component, InversifyJS DI (mirrors the Dagger 2
`AppComponent` composition-root pattern from the Android reference project), apisauce + hand-written
DTOs for networking, expo-sqlite for persistence, react-native-mmkv for local key/value storage,
React Navigation for navigation, i18next for localization.

| area | choice |
|---|---|
| Language | **TypeScript** (strict) |
| Runtime | **Expo SDK 54+** / **React Native 0.81+** |
| Build | `expo run:ios` / `expo run:android`, **EAS Build** for release; native folders generated by `expo prebuild` — never hand-edited |
| UI | **React Native core** wrapped by project base components (`Screen`, `Text`, `Button`, `TextField`, `Toggle`) — no ad-hoc raw styling |
| Arch | **MVVM** — MobX `BaseViewModel` + `observer()` `Screen` component |
| DI | **InversifyJS** — one composition root (`container.ts`), `Symbol` tokens, `useViewModel()` hook |
| State | **MobX** + `mobx-react-lite` (`observer`, `makeAutoObservable`) |
| Navigation | **React Navigation** (`native-stack` + `bottom-tabs`) |
| Network | **apisauce** + hand-written DTOs (`ApiService` interface / `ApiServiceImpl`) |
| Persistence | **expo-sqlite** (`RoomService`, Android-Room-style naming) |
| Local storage | **react-native-mmkv** (`StorageService`) |
| i18n | **i18next** / **react-i18next** — `en.ts` / `vi.ts`, Vietnamese default |
| Crash/analytics | Firebase Crashlytics |
| Test | **Jest** + `@testing-library/react-native` (where the project has tests) |

Full version catalog + build config: [`skills/react-native/references/stack.md`](skills/react-native/references/stack.md).

## How a project uses it

1. In the project's repo-root `vibe_setting.json`: `"techStack": "react-native-ai-skill"`.
2. Run **`/init-project`** — it downloads this tree into the project's local (git-ignored)
   `.claude/`. Claude Code then discovers `skills/react-native` natively and applies it
   automatically (no manual invocation needed — the skill's `description` triggers it).

Everything here is **generic** — no app id, endpoints, or credentials. A consuming project keeps its
own `app.json`/`app.config.ts` bundle identifiers, base URLs, and secrets in `app/config/`, never
here.
