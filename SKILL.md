# React Native skill — Expo + Ignite (TypeScript · MVVM · MobX · InversifyJS DI)

Playbook for implementing React Native tasks in an Expo/Ignite-based app. Generic — no app-specific
endpoints or credentials.

## Stack
- **Language: TypeScript** (strict), **React Native 0.81+ / Expo SDK 54+**, iOS + Android app.
- **Build: Expo** (`expo run:ios` / `expo run:android`), EAS Build for release binaries. Native
  `ios/`/`android/` folders are generated by `expo prebuild` — never hand-edit them.
- **Architecture: MVVM** — `Screen` (function component, `observer()`) + `ViewModel`
  (MobX class extending `BaseViewModel`, `isLoading`/`error`/`runAction()`). No domain/usecase layer —
  the ViewModel calls `repository` directly.
- **DI: InversifyJS** — one composition root (`app/di/container.ts`), `ContainerModule`s per concern,
  `Symbol` tokens in `app/di/types.ts`, `useViewModel()` hook resolves a ViewModel into a screen via
  `container.get()`. Constructor injection everywhere (mirrors the Dagger 2 `AppComponent` pattern).
- **UI: React Native core components** wrapped by this project's own base components
  (`Screen`, `Text`, `Button`, `Icon`, `TextField`, `Toggle`, `LoadingIndicator` in `app/components/`)
  — prefer these over raw `View`/`Text`/`TextInput`. **No StyleSheet-less inline magic numbers** —
  use `app/theme/` (`colors`, `spacing`, `typography`).
- **Navigation: React Navigation** — `@react-navigation/native-stack` for the root stack
  (`AppNavigator`), `@react-navigation/bottom-tabs` for `MainTabNavigator`.
- **State: MobX + mobx-react-lite** — `observer(Component)`, `makeAutoObservable`/`@observable` in
  ViewModels; `app/stores/` for cross-screen shared singletons (e.g. `authStore`), `@injectable()`.
- **Networking: apisauce** — `Api` client in `data/remote/api/index.ts` (Bearer-token attachment);
  `ApiService` is a bare interface (`data/remote/api/ApiService.ts`), `ApiServiceImpl` implements it
  with one method per endpoint, each going through the shared `request()` unwrap helper.
- **Persistence: expo-sqlite** — `AppDatabase`/`RoomService(Impl)` in `data/local/room/` (Android
  `Room`-style naming kept for parity with the Android/Kotlin reference stack).
- **Local storage: react-native-mmkv** — `StorageService` wrapper in `data/local/storage/`.
- **i18n: i18next / react-i18next** — `app/i18n/en.ts`, `app/i18n/vi.ts` (Vietnamese is the default
  locale), `translate(key)`.
- **Env/URLs**: never hardcoded — read from `app/config/` (`API_URL`, `MASTER_API_URL`, …).

## Where things live (`app/`)
- `di/` — `container.ts` (composition root), `types.ts` (Symbol tokens), `useViewModel.ts`,
  `modules/dataModule.ts` (StorageService/AuthStore/Api/ApiService/AppDatabase/RoomService/Repository),
  `modules/viewModelModule.ts` (ViewModel bindings).
- `viewmodels/base/BaseViewModel.ts` — shared MobX base: `isLoading`, `error`, `runAction()`,
  property-injected `repository`.
- `stores/` — MobX singletons for cross-screen shared state (`authStore.ts`), `@injectable()`.
- `screens/<ScreenName>/` — `<ScreenName>Screen.tsx` (view + styles) + `<ScreenName>ViewModel.ts`
  (all logic/state, only if the screen has state).
- `navigators/` — `AppNavigator` (root stack) + `MainTabNavigator` (bottom tabs).
- `components/` — shared UI: `Screen`, `Text`, `Button`, `Icon`, `TextField`, `Toggle`,
  `LoadingIndicator`, …
- `theme/` — `colors`, `spacing`, `typography`.
- `i18n/` — `en.ts` / `vi.ts` + `translate()`.
- `config/` — env config.
- `data/`
  - `Repository.ts` (interface) / `AppRepositoryImpl.ts` (impl) — `{ apiService; roomService;
    storageService }`, the one thing a ViewModel injects.
  - `remote/api/` — `index.ts` (apisauce client), `ApiService.ts` (interface), `ApiServiceImpl.ts`
    (impl), `apiProblem.ts`, `master/` (second base URL, if the project has one).
  - `model/api/item/` — domain shapes returned to screens, one per file.
  - `model/api/response/<domain>/` — wire-shape DTOs, one per file.
  - `local/room/` — `AppDatabase`/`RoomService(Impl)`/`<X>Dao(Impl)`.
  - `local/storage/` — MMKV load/save/remove + `StorageService`.
- `utils/` — date formatting, logging, crash reporting — no data-layer code here.

## Build & run
- Start: `npx expo start --dev-client`. iOS: `npx expo run:ios`. Android: `npx expo run:android`.
- Type check: `npx tsc --noEmit -p . --pretty` — this is the **Definition-of-done build check**
  (there is no compiled binary gate like `xcodebuild`/`gradlew assembleDebug` for a JS/TS app; a
  clean type-check + a successful Metro bundle is the bar). Run `scripts/skill-probe.sh` /
  `scripts/typecheck.sh` — see below.
- Lint: `npx eslint . --fix`.
- Dependencies: `npm install` / `yarn` per the project's lockfile; `npx expo install --fix` to align
  native module versions with the pinned Expo SDK.
- Tests (where the project has them): `npx jest`.

## Conventions
- Match **TypeScript + functional components** style; wrap the screen component in `observer(() =>
  { ... })` (`mobx-react-lite`) so MobX reactivity works — skip `observer()` only when a screen
  truly has no ViewModel/observable state.
- New screen = `app/screens/<Name>/<Name>Screen.tsx` (component + its `$name: ThemedStyle<T>` style
  constants in the same file, no separate `style.ts`/`index.tsx`) + `<Name>ViewModel.ts` (a MobX
  class extending `BaseViewModel`, only if the screen holds state/calls the API).
- Resolve the ViewModel via `useViewModel(XxxViewModel)` (`@/di/useViewModel`) at the top of the
  screen — never `new XxxViewModel()` directly, and never inject `ApiService`/`RoomService`/
  `StorageService` straight into a ViewModel (always via `this.repository`, property-injected on
  `BaseViewModel`).
- **`makeAutoObservable` throws on any class with a superclass** — every ViewModel extends
  `BaseViewModel`, so always use `makeObservable(this, { ... })` with explicit annotations covering
  both the ViewModel's own fields *and* the inherited `isLoading`/`error`. Use `actionBound` (not
  `action` or `action.bound`) for any method passed directly as an event handler
  (`onPress={viewModel.increment}`); a plain `action` method loses `this` when passed that way.
- Call the API through `this.runAction(async () => { ... this.repository.apiService.getX() ... })`
  — don't call `apiService` directly outside of `runAction`, and don't create a per-screen
  repository class; every endpoint lives once on the shared `ApiService`.
- `ApiService.ts` stays a bare interface — no apisauce calls, no inline DTO `interface`s. Add a
  method signature there, implement it in `ApiServiceImpl.ts` (one apisauce call + one DTO→domain
  mapping per method), and give the DTO/domain shape their own files under `data/model/api/`.
- Register a new screen's route in `app/navigators/AppNavigator.tsx` (stack) or
  `MainTabNavigator.tsx` (bottom tab), add the entry to `app/navigators/navigationTypes.ts`, and
  bind its ViewModel in `app/di/modules/viewModelModule.ts`.
- A UI piece worth its own file but used by only one screen stays **local** —
  `app/screens/<Name>/components/<Sub>/<Sub>.tsx` — not `app/components/`. Promote it to
  `app/components/<Name>/` only once a second screen actually needs it (YAGNI).
- Localize strings via `translate('screen_key')` / `tx="screen_key"` (i18next) — never a hardcoded
  literal in JSX — and add the key to **both** `app/i18n/en.ts` and `app/i18n/vi.ts`.
- Log with `app/utils/logger.ts` (`logger.d/i/w/e`) — not bare `console.log` in production code.
- Avoid hardcoding colors/spacing — use `app/theme/colors` / `app/theme/spacing` via `themed($style)`.
- Reuse an existing base component (`Screen`, `Text`, `Button`, `TextField`, `Toggle`,
  `LoadingIndicator`) before adding a new one.

## Definition of done
- [ ] `npx tsc --noEmit -p .` succeeds (run `scripts/typecheck.sh` — see below).
- [ ] Follows package layout + conventions (TypeScript, MVVM, MobX, InversifyJS, apisauce, i18next).
- [ ] Manual verify on iOS/Android simulator or device (`expo run:ios` / `expo run:android`).

## Scripts (bundled — fetch on demand via get_skill_file)
These live in this skill's repo under `scripts/`. Fetch a script with `get_skill_file { id, path }`,
write it to a temp/scratch file, then run it. `<this skill id>` is the id you were injected with.

- **`scripts/skill-probe.sh`** — self-check that proves skill scripts reach you. Fetch, save to temp,
  run `bash <tmp> hello`; it prints `SKILL-PROBE OK`.
  `get_skill_file { id: "<this skill id>", path: "scripts/skill-probe.sh" }` → `$TMP` → `bash $TMP hello`
- **`scripts/typecheck.sh`** — Definition-of-done check. Fetch it, save to temp, run
  `bash <tmp> /path/to/react-native-project` from any directory; it runs `tsc --noEmit` and prints
  `typecheck PASS` / `FAIL`.
